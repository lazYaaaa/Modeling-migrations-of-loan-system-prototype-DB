## 🔒 СИСТЕМА БЛОКИРОВОК (Алгоритм 4.2)

### Как работает:

```
1. СОСТОЯНИЕ ДО
   Заявка в БД со статусом "Новая"
   Таблица application_locks пуста
   Все сотрудники видят 🔓 (свободна)

2. СОТРУДНИК НАЖИМАЕТ "ОБРАБОТАТЬ"
   API:
   - Проверяет: SELECT * FROM application_locks WHERE application_id = 1
   - Если пусто → INSERT в application_locks
   - Если есть → return ошибка "уже обрабатывается"

3. БЛОКИРОВКА УСТАНОВЛЕНА
   application_locks содержит:
   - application_id = 1
   - locked_by = 2 (employee_id)
   - timeout_at = NOW() + 30 минут
   
4. ИНТЕРФЕЙС ОБНОВЛЯЕТСЯ
   - Красный индикатор 🔒
   - Таймер: "осталось 29:45"
   - Кнопки редактирования активны
   
5. ТАЙМЕР РАБОТАЕТ
   JavaScript каждые 5 секунд:
   - Запрашивает текущую заявку
   - Вычисляет оставшееся время
   - Обновляет таймер в интерфейсе
   
6. СОТРУДНИК ЗАВЕРШАЕТ
   Нажимает "Одобрить" или "Отклонить"
   
   API:
   - Создает договор (если одобрено)
   - DELETE FROM application_locks WHERE application_id = 1
   - Обновляет статус заявки
   
7. БЛОКИРОВКА СНЯТА
   - Таблица application_locks пуста
   - Другие сотрудники видят 🔓 (свободна)
   - Можно обрабатывать

8. ЕСЛИ ЗАБЫТЬ ЗАВЕРШИТЬ
   Через 30 минут:
   - timeout_at < NOW()
   - Приложение автоматически DELETE запись
   - Блокировка снимается (failsafe)
```

### Таблица в БД:
```sql
CREATE TABLE application_locks (
    lock_id SERIAL PRIMARY KEY,
    application_id INTEGER UNIQUE,  -- какая заявка
    locked_by INTEGER,               -- кто (employee_id)
    locked_at TIMESTAMP,             -- когда
    timeout_at TIMESTAMP             -- когда разблокируется
);
```
