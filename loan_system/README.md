# Система управления кредитованием

Полнофункциональное веб-приложение для управления жизненным циклом кредитных продуктов в банке.

## Функциональность

### 1. Управление клиентской базой
- Централизованное хранение персональных данных клиентов
- Просмотр и управление контактной информацией
- История кредитов каждого клиента

### 2. Обработка заявок
- Просмотр всех кредитных заявок
- Статусы заявок: Новая, В работе, Одобрена, Отклонена, Архив
- Фильтрация и сортировка заявок

### 3. Система блокировок (Lock Management)
- Эксклюзивный доступ при обработке заявки
- Автоматический timeout (30 минут)
- Предотвращение конкурентного редактирования
- Индикаторы статуса блокировки в реальном времени

### 4. Обработка заявок
- Редактирование параметров кредита
- Одобрение заявок с автоматическим созданием договора
- Отклонение заявок в архив
- Формирование графика платежей

### 5. Договорная работа
- Автоматическое создание кредитных договоров
- Уникальные номера договоров и счетов
- Сохранение всех параметров

### 6. Управление платежами
- Автоматическое формирование графика платежей
- Аннуитетные платежи
- Отслеживание статуса платежей

## Требования

- PHP 7.4+
- PostgreSQL 12+
- Apache с поддержкой mod_rewrite (или другой веб-сервер)

## Установка

### 1. Подготовка базы данных

Убедитесь, что база данных `loan_system` создана и содержит все необходимые таблицы:

```sql
-- Запустите скрипт main_migration_file.sql
psql -U postgres -d loan_system -f main_migration_file.sql
```

### 2. Конфигурация

Отредактируйте файл `api/config/database.php`:

```php
$db_host = 'localhost';
$db_port = 5432;
$db_name = 'loan_system';
$db_user = 'postgres';
$db_password = 'ваш_пароль';
```

### 3. Запуск приложения

#### Вариант 1: Встроенный PHP сервер
```bash
cd loan_system/frontend
php -S localhost:8000
```

Откройте браузер: http://localhost:8000

#### Вариант 2: Apache
```
Скопируйте папку loan_system в htdocs (XAMPP) или public_html
Откройте: http://localhost/loan_system/frontend
```

## Использование

### Вход в систему
1. Используйте логин из таблицы `employees` (например: user_1, user_2)
2. Пароль не проверяется в демо-версии

### Обработка заявки (Алгоритм 4.2)

1. **Шаг 1**: Перейдите на вкладку "Заявки"
2. **Шаг 2**: Найдите необработанную заявку и нажмите "Открыть"
3. **Шаг 3**: Нажмите кнопку "Обработать заявку"
   - Система попытается заблокировать заявку для вас
   - Если заявка уже заблокирована другим сотрудником - вы получите ошибку
4. **Шаг 4**: Отредактируйте параметры кредита (если необходимо)
5. **Шаг 5**: Выберите действие:
   - **Одобрить заявку** - создает договор и график платежей
   - **Отклонить заявку** - отправляет в архив
6. **Шаг 6**: Блокировка автоматически снимается

### Система блокировок

#### Как это работает
- Когда сотрудник нажимает "Обработать заявку", она блокируется для других
- Блокировка действует 30 минут
- Другие сотрудники видят, кто обрабатывает заявку
- После истечения времени блокировка автоматически снимается

#### Управление блокировками
- **Зеленый индикатор 🔓** - заявка свободна для обработки
- **Красный индикатор 🔒** - заявка заблокирована
- **Таймер** - показывает оставшееся время блокировки

## API Endpoints

### Заявки
- `GET /api/applications` - получить все заявки
- `GET /api/applications/{id}` - получить заявку
- `PUT /api/applications/{id}` - обновить заявку
- `POST /api/applications/{id}/lock` - заблокировать заявку
- `DELETE /api/applications/{id}/lock` - разблокировать заявку
- `POST /api/applications/{id}/approve` - одобрить заявку
- `POST /api/applications/{id}/reject` - отклонить заявку

### Клиенты
- `GET /api/clients` - получить всех клиентов
- `GET /api/clients/{id}` - получить клиента
- `GET /api/clients/{id}/documents` - документы клиента
- `GET /api/clients/{id}/history` - история кредитов

### Справочники
- `GET /api/employees` - получить сотрудников
- `GET /api/products` - получить продукты

### Аутентификация
- `POST /api/auth` - вход в систему

## Описание алгоритма обработки заявки

```
АЛГОРИТМ 4.2: ОБРАБОТАТЬ ЗАЯВКУ

1. Нажать на вкладку "Обработать заявки" (список необработанных)
2. Выбрать заявку из списка
3. Проверить блокировку для выбранной заявки
   
   ВЕТКА 1: БЛОКИРОВКА ЕСТЬ (занято другим)
   → Получена ошибка: "Заявка уже обрабатывается другим сотрудником"
   
   ВЕТКА 2: БЛОКИРОВКИ НЕТ (можно обрабатывать)
   → Блокировка установлена:
     • locked = true
     • locked_by = текущий_сотрудник
     • lock_time = текущее_время
     • timeout = 30 минут
     • Запущен таймер

4. Редактирование заявки (эксклюзивный доступ)
   • Изменить поля кредита
   • Нажать кнопку: ПРИНЯТЬ или ОТКЛОНИТЬ

5. Решение принято
   → Снятие блокировки (освобождение ресурса)
   
   ЕСЛИ "ПРИНЯТЬ":
   • Статус = "Одобрено"
   • Создан кредит
   
   ЕСЛИ "ОТКЛОНИТЬ":
   • Статус = "Архив"
   • Отправлена в архив

6. Конец алгоритма
   • Обновить список заявок
   • Вернуться к шагу 1
```

## Технологические решения

### Backend (PHP)
- Модельный подход для разделения логики
- PDO для работы с БД
- REST API для взаимодействия с фронтенд

### Frontend (Vanilla JavaScript)
- Асинхронные запросы (Fetch API)
- Модальные окна для детальной информации
- Real-time таймеры для блокировок
- Локальное хранилище (localStorage) для сессии

### База данных (PostgreSQL)
- Таблица `application_locks` для управления блокировками
- Внешние ключи для целостности данных
- Автоматическое удаление истекших блокировок
